Documentation / Architecture

Architecture and task repositories

ALA is a small execution substrate. It owns generic ways to run work; a task repository owns the meaning and method of one coherent task family. An A-Skill is an Achilles skill inside that repository.

Boundary of responsibility

Generic ALA capabilities include direct, fast, and deep LLM calls; coding-agent and agentic execution; web or research access; and isolated temporary workspaces. Translation, reference verification, controlled-natural-language conversion, SOP Lang planning, and scientific writing remain task-specific A-Skills.

Repository contract

Each task repository must describe the request types it covers, selection evidence, input and output expectations, available A-Skills, constraints and verification procedures, and generic capabilities those skills may request. This description participates in routing; it is not documentation-only metadata.

AchillesAgentLib integration point

The intended default follows the existing AchillesAgentLib/MainAgent pattern: discover skills, register them, select a capability, and route execution to the appropriate subsystem. ALA hides that library-level complexity from its callers while preserving compatible model tags and session behavior.

Imported skills remain local to their task repository. They do not become host-project DS files or standalone pages under this documentation tree.
