Documentation / Architecture

Runtime and task-repository architecture

ALA supplies reusable execution services. Independent task repositories supply domain methods through A-Skills. This boundary lets a task family evolve without extending the central runtime.

Responsibility boundary

A task repository decides which requests it covers, which A-Skill performs the work, which inputs and outputs are valid, and how the result is checked. ALA decides how the selected method runs in the current environment. It maps requested generic execution capabilities to configured models, authenticated agents, research access, or an isolated workspace.

AchillesAgentLib skill families

An A-Skill is a normal AchillesAgentLib skill. A Code Skill runs a supplied module. An Orchestration Skill coordinates several actions. A DBTable Skill describes table fields and operations. A Dynamic Code Generation Skill creates code during task execution. The owning repository selects the family that fits its method.

Discovery and portability

ALA loads configured task repositories through AchillesAgentLib conventions wherever practical. Each semantic repository description becomes routing evidence, not only explanatory prose. Imported A-Skill instructions, code, pages, and specifications remain in the repository that owns them.

Definitions

Code Skill
An AchillesAgentLib skill, conventionally described by cskill.md, that runs a supplied module.
Orchestration Skill
An AchillesAgentLib skill, conventionally described by oskill.md, that coordinates multiple skills, tools, or agents.
DBTable Skill
An AchillesAgentLib skill, conventionally described by tskill.md, that defines table fields and database operations.
Dynamic Code Generation Skill
An AchillesAgentLib skill, conventionally described by dcgskill.md, that generates and executes code during a task.
