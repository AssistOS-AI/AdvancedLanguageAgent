Advanced Language Agent Documentation

Advanced Language Agent (ALA) is a system-installed CLI for language and documentation tasks. A human or agent submits an instruction and optional input; the CLI runs the request through AchillesAgentLib or a detected coding agent and returns the requested result in one-shot mode or across an explicitly interactive process.

ALA mounts exactly the directories the caller supplies through --cwd and --folder. It does not discover, create, mount or overlay task skills; callers own their directory layout and any task methodology.

From instruction to result

A request may carry input through command arguments, standard input, a URL, or a file. General execution runs through MainAgent. When a coding agent is selected explicitly with --ca/--agent, ALA delegates the request to that backend inside its sandbox against the caller's mounted directories. The runtime writes the requested result to standard output or a file, while diagnostics use a separate channel.

A one-shot command creates a new runtime. Reusing --cwd alone does not resume a conversation. Explicit --session-id and --resume-session restore the same native conversation and pinned coding backend across processes. An interactive command retains these in memory until exit. A caller-supplied cwd is never deleted by ALA, and ALA retains the temporary directory it creates when --cwd is omitted. See persistent session commands for continuation and live input.

CLI and user configuration

The executable is ala. The versioned JSON configuration uses $HOME/.ala/config.json. ALA_CONFIG_PATH selects another root directory and moves ALA state below its .ala/ child, while --config <file> has the highest priority for one command. Legacy taskRepositories fields in existing files are ignored.

Payloads use --text, --file, --url, or --stdin, and --output writes the clean result to a protected file. Directories are supplied with --cwd <path> [as <alias>] and repeatable --folder <path> [write] [as <alias>]. The command reference documents every command and option.

ala agent list reports the names of detected Codex, OpenCode, and Pi backends. In an interactive session, /agent <name> models lists a backend's available model identifiers, /agent <name> model <model-name> persists its selection, and /agent <name> model default removes the override. --agent auto forces delegation using the configured priority, while --agent codex, --agent opencode, or --agent pi selects one backend explicitly. Every backend and model-list process runs through Linux Bubblewrap; ALA mounts the already installed backend runtime read-only, never installs a task-local copy, and never falls back to unsandboxed execution. Interactive coding-agent output replaces the waiting indicator as soon as a supported event arrives, while the normalized final answer remains on standard output. Coding-agent web search is off by default; bare --websearch enables it for one invocation, --websearch on|off is the explicit override form, and interactive /websearch on|off saves and immediately applies it. The setting controls Codex and OpenCode; Pi remains unchanged because ALA does not add third-party web-search extensions.

Embedding orchestrators may supply --home, --cwd, --folder, --task or --taskFile, --MCPServers, and --ca. The explicit home contains coding-agent configuration, the explicit cwd remains persistent, each mounted directory stays at its canonical path or alias, and MCP URL overrides are transient.

Product and repository boundaries

ALA is generic execution infrastructure. It does not implement or distribute task-specific SKILL.md definitions and does not require any catalog. A caller that owns task methods installs them in its own working directory and references them in its own prompt; ALA simply runs the selected backend with the directories it was given.

The generic coding-agent Code Skill is internal execution infrastructure that bridges to Codex, OpenCode, or Pi. It is not a caller task skill.

Imported task skills and their design specifications stay in their owning repositories. The core documentation describes how callers integrate with the runtime without copying skill-specific documentation.

Runtime defaults and verification

Direct model work uses LLMAgent. Explicit coding-agent selection always uses the chosen backend; otherwise MainAgent performs general execution.

Coding style, source layout, file-size limits, and modular test organization are defined by DS001. Tests are grouped by concern and independently cover argument parsing, input handling, configuration persistence and precedence, coding-agent delegation, mount layout, AchillesAgentLib integration, output separation, and result-file protection.
