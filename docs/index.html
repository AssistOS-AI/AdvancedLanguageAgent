Advanced Language Agent Documentation

Advanced Language Agent (ALA) is a system-installed CLI for language and documentation tasks. A human or agent submits an instruction and optional input; the CLI selects a reusable task method, runs it through an eligible backend, and returns the requested result in one-shot mode or across an explicitly interactive process.

ALA uses AchillesAgentLib for general model-backed requests and its internal coding-agent adapter. Optional task skills are independent Anthropic-style SKILL.md descriptors discovered directly by ALA and executed by Codex, OpenCode, or Pi. Task repositories do not need AchillesAgentLib skill descriptors.

From instruction to result

A request may carry input through command arguments, standard input, a URL, or a file. With no configured task repository, the runtime executes the general request through MainAgent. When task skills and an authenticated coding agent are available, the agent selects a matching descriptor, reads its SKILL.md, and follows its methodology. The runtime writes the requested result to standard output or a file, while diagnostics use a separate channel.

A one-shot command creates a new runtime for one request and removes any coding-agent workspace when that process exits; a later command does not inherit its ALA conversation or native continuation. An interactive command retains the runtime, lazily created workspace, pinned coding backend and native continuation until the user exits. Explicit folder mounts can expose persistent caller data in either mode, but they do not turn the temporary ALA workspace into persistent storage.

CLI and user configuration

The executable is ala, and general requests require no task repository. Register optional persistent task repositories with ala repo add <git-url>, inspect them with ala repo list, and unregister them by repository name with ala repo remove <name>. The registered path and original Git URL remain valid removal identifiers. Persistent additions are cloned into the ALA data directory; ALA_TASK_REPOSITORIES supplies platform-delimited local repository paths through the environment. Interactive /repo add and /repo remove commands refresh the active skill catalog before the next prompt, and TAB completes registered names after /repo remove . The versioned JSON configuration uses ~/.config/ala/config.json; ALA_CONFIG_PATH selects another file, and --config has the highest priority for one command.

Use --skill to select an Anthropic task skill for coding-agent execution. Without it, a coding agent selects from a populated catalog; when no task catalog or coding agent is available, MainAgent performs general execution. Payloads use --text, --file, --url, or --stdin, and --output writes the clean result to a protected file. The command reference documents every command and option.

ala agent list reports the names of detected Codex, OpenCode, and Pi backends. In an interactive session, /agent <name> models lists a backend's available model identifiers, /agent <name> model <model-name> persists its selection, and /agent <name> model default removes the override. --agent auto forces delegation using the configured priority, while --agent codex, --agent opencode, or --agent pi selects one backend explicitly. Every backend and model-list process runs through Linux Bubblewrap with an isolated /workspace; ALA mounts the already installed backend runtime read-only, never installs a task-local copy, and never falls back to unsandboxed execution. Interactive coding-agent output replaces the waiting indicator as soon as a supported event arrives, while the normalized final answer remains on standard output. Coding-agent web search is off by default; bare --websearch enables it for one invocation, --websearch on|off is the explicit override form, and interactive /websearch on|off saves and immediately applies it. The setting controls Codex and OpenCode; Pi remains unchanged because ALA does not add third-party web-search extensions.

Repeatable --folder <path> [write|w] options expose explicitly authorized directories under /workspace/.ala/folders and force coding-agent execution. The default is strict read-only; only write or w requests read-write access. Interactive /folder add, /folder list, and /folder remove commands manage the session mount set without persisting it in ALA configuration.

Product and repository boundaries

Independently versioned task repositories provide task descriptions and SKILL.md task skills for coherent language-task families. Their semantic descriptions participate in routing. The CLI contains generic infrastructure and does not hard-code those domain methods.

Task skills are repository-owned Anthropic-style `SKILL.md` entries; they are not hard-coded in the CLI runtime.

This repository defines the core runtime contract. Imported task skills and their design specifications stay in their owning task repositories. The core documentation therefore describes how those repositories integrate with the runtime without copying their skill-specific documentation.

Runtime defaults and verification

Explicit task-skill selection takes precedence and always uses a coding agent. Otherwise a populated task catalog is offered to the first available coding agent; an empty or unavailable catalog leaves general execution with MainAgent. Experimental symbolic routing is off by default and can be enabled for an interactive session with /symbolic detection on. Direct model work uses LLMAgent.

Coding style, source layout, file-size limits, and modular test organization are defined by DS001. Tests are grouped by concern and independently cover argument parsing, input handling, configuration persistence and precedence, repository aggregation, explicit and default routing, AchillesAgentLib integration, output separation, and result-file protection.

Task skill availability

The core repository does not implement or distribute task-specific SKILL.md-defined skills. General execution remains available with an empty skill catalog. ALA validates only Anthropic SKILL.md descriptors in task repositories and mounts each discovered skill into the coding-agent workspace. The generic coding-agent Code Skill is internal execution infrastructure and does not add a domain method to the task catalog.
