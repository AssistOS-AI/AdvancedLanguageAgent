Advanced Language Agent Documentation

Advanced Language Agent (ALA) is a system-installed CLI for language and documentation tasks. A human or agent submits an instruction and optional input; the CLI selects a reusable task method, runs it through an eligible backend, and returns the requested result.

ALA uses AchillesAgentLib to discover and execute A-Skills. Each A-Skill owns the method and checks for one task. ALA owns reusable routing, model, agent, research, workspace, session, and retry services.

From instruction to result

A request may carry input through command arguments, standard input, a URL, or a file. The runtime selects an A-Skill, resolves its requested generic execution capabilities, and writes the requested result to standard output or a file. Diagnostics use a separate channel so another program can consume the result reliably.

Product and repository boundaries

Independently versioned task repositories provide task descriptions and A-Skills for coherent language-task families. Their semantic descriptions participate in routing. The CLI contains generic infrastructure and does not hard-code those domain methods.

An A-Skill is an AchillesAgentLib skill in a task-facing role. It is not a separate file format or a copy embedded in the CLI runtime.

This repository defines the core runtime contract. Imported task skills and their design specifications stay in their owning task repositories. The core documentation therefore describes how those repositories integrate with the runtime without copying their skill-specific documentation.

Runtime defaults and verification

Explicit task or A-Skill selection takes precedence. Otherwise the runtime uses the MainAgent-compatible selection path. Experimental symbolic detection may run first, but uncertainty returns the request to the default selector. Direct model work uses LLMAgent; stronger models, authenticated agents, research access, and temporary workspaces are selected only when the task method requires them.

Coding style, source layout, file-size limits, and modular test organization are defined by DS001. Tests are grouped by concern and independently cover input handling, routing, executor selection, configuration precedence, workspace lifecycle, retry bounds, and result-stream separation.

Task skill availability

The core repository does not implement or distribute task-specific A-Skills. A deployment obtains its available task methods from configured task repositories, so the product skill catalog can vary independently from the core installation.

Documentation map

Architecture explains the boundary between the runtime and task repositories. Routing covers task selection and backend selection. Execution covers models, agents, workspaces, and feedback. Integration covers deployment and routing evaluation. The specification matrix contains the authoritative contracts.

Definitions

Advanced Language Agent (ALA)
The CLI and generic runtime that select and execute reusable language-task methods.
AchillesAgentLib
The external library that provides skill discovery, MainAgent routing, LLMAgent, sessions, model tags, and compatible execution regimes.
A-Skill
A reusable AchillesAgentLib skill supplied by a task repository, containing instructions and optional code for one coherent task.
Task repository
An independently versioned package that describes one task family, its A-Skills, routing evidence, inputs, outputs, constraints, and verification procedures.
Generic execution capability
A reusable runtime service such as model execution, an authenticated agent, research access, multi-step execution, or an isolated workspace.
MainAgent
The AchillesAgentLib coordinator used for default discovered-skill selection and routing to a compatible execution subsystem.
LLMAgent
The AchillesAgentLib class through which the runtime performs configured direct LLM interactions.
