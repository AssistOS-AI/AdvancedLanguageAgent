Advanced Language Agent Documentation

Advanced Language Agent (ALA) is a system-installed CLI for language and documentation tasks. A human or agent submits an instruction and optional input; the CLI selects a reusable task method, runs it through an eligible backend, and returns the requested result.

ALA uses AchillesAgentLib to execute general requests and to discover and execute optional A-Skills. Each A-Skill owns the method and checks for one specialized task. ALA owns reusable routing, model, agent, research, workspace, session, and retry services.

From instruction to result

A request may carry input through command arguments, standard input, a URL, or a file. With no configured task repository, the runtime executes the general request through MainAgent. When task methods are installed, it may select an A-Skill and resolve its requested generic execution capabilities. The runtime writes the requested result to standard output or a file, while diagnostics use a separate channel.

CLI and user configuration

The executable is ala, and general requests require no task repository. Register optional persistent task repositories with ala repo add <path>, inspect them with ala repo list, and unregister them with ala repo remove <path>. The versioned JSON configuration uses $XDG_CONFIG_HOME/ala/config.json or ~/.config/ala/config.json; --config selects another file.

Use --skill for explicit A-Skill execution or omit it for MainAgent general execution and optional skill selection. --task-repo adds a repository for one invocation. Payloads use --text, --file, --url, or --stdin, and --output writes the clean result to a protected file. The command reference documents every command and option.

Product and repository boundaries

Independently versioned task repositories provide task descriptions and A-Skills for coherent language-task families. Their semantic descriptions participate in routing. The CLI contains generic infrastructure and does not hard-code those domain methods.

An A-Skill is an AchillesAgentLib skill in a task-facing role. It is not a separate file format or a copy embedded in the CLI runtime.

This repository defines the core runtime contract. Imported task skills and their design specifications stay in their owning task repositories. The core documentation therefore describes how those repositories integrate with the runtime without copying their skill-specific documentation.

Runtime defaults and verification

Explicit A-Skill selection takes precedence. Otherwise the runtime uses MainAgent to execute the request, with or without available skills. Experimental symbolic routing may run before skill selection only when uncertainty returns the request to the default path. Direct model work uses LLMAgent; stronger models, authenticated agents, research access, and temporary workspaces are selected only when the request and deployed executor support require them.

Coding style, source layout, file-size limits, and modular test organization are defined by DS001. Tests are grouped by concern and independently cover argument parsing, input handling, configuration persistence and precedence, repository aggregation, explicit and default routing, AchillesAgentLib integration, output separation, and result-file protection.

Task skill availability

The core repository does not implement or distribute task-specific A-Skills. General execution remains available with an empty skill catalog. A deployment obtains optional specialized task methods from configured task repositories, so the catalog can vary independently from the core installation.
