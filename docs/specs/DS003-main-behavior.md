## Introduction

[Advanced Language Agent (ALA)](index.html) lets a human or calling agent submit a language-oriented task through the `ala` command and receive the requested result without integrating [AchillesAgentLib](wiki.html#definition-achilles-agent-lib) or a model provider directly. This specification contains the implemented behaviors that determine that user outcome.

## Core Content

### Main Behavior Components

| Name | Explanation |
| --- | --- |
| Single-shot and interactive request execution | A human or agent supplies an instruction and optional payloads, and ALA returns a clean result once or across a retained interactive session. |
| Configured AchillesAgentLib execution | ALA resolves AchillesAgentLib, applies model and runtime overrides, runs the request through [MainAgent](wiki.html#definition-main-agent), preserves cancellation and cleanup, and returns the result. |
| Authenticated coding-agent delegation | ALA detects installed agent CLIs, executes every agent process inside Bubblewrap, and mounts exactly the caller-supplied `--cwd` and `--folder` directories at their canonical or aliased paths. |

### Single-shot and interactive request execution

A human or calling agent starts this behavior with `ala [options] [instruction...]`. ALA must combine positional instruction text with ordered `--text`, `--file`, `--url`, and `--stdin` payloads, and also accept orchestration-oriented `--task` or `--taskFile` prompts. Each process builds a new runtime. Explicit `--session-id` and `--resume-session` preserve the native coding-agent conversation across processes, and ALA records each such conversation in an append-only [session transcript](wiki.html#definition-session-transcript) at `$ALA_SESSIONS/sessions/<uuid>.jsonl`, defaulting to `<cwd>/.ala`, which embedding applications read through the `advanced-language-agent/transcript` package export. `--resume-session` takes the native continuation from that transcript. Ordinary one-shot execution has no implicit continuation and writes no transcript. Coding-agent execution uses the explicit `--cwd` directory when supplied and otherwise creates and retains a private temporary workspace. `--home` selects the coding-agent configuration home. During an interactive session, lines beginning with `/` are local commands; arbitrary folder-mount commands are not supported.

The observable result must contain only the requested content on standard output or in the file selected by `--output`. Diagnostics, interactive prompts, and supported live coding-agent events must use standard error. While terminal input and standard error are both interactive, every MainAgent or coding-agent wait must display a repeating `Thinking.`, `Thinking..`, and `Thinking...` status on one diagnostic line. The first live coding-agent event must clear and stop that indicator before visible assistant, command, tool, or native provider output is written, while the normalized final answer remains the standard-output result. The status must clear on success, failure, or interruption and remain disabled for redirected or non-interactive streams. ALA must refuse to replace an existing output file unless the caller supplies `--force`, limit each file or URL payload to 10 MiB, limit their aggregate size to 32 MiB, stop URL retrieval after 30 seconds, and convert interruption into exit code `130`. These hidden protections prevent an accepted request from consuming unbounded input, contaminating machine-readable output, or silently destroying an existing result file. DS004 defines the detailed session and input contracts.

### Configured AchillesAgentLib execution

Every accepted request must pass through a resolved AchillesAgentLib MainAgent. Direct model execution must use its [LLMAgent](wiki.html#definition-llm-agent), while explicit coding-agent execution must use MainAgent's Code Skill subsystem without making an LLMAgent model call. ALA must resolve the library from `--achilles-path` or `ACHILLES_AGENT_LIB_PATH`, then a sibling checkout, then the installed `ploinky-agent-lib` package. A selected path that cannot be loaded must stop execution with repository exit code `4` instead of silently choosing another source.

ALA must apply `--model`, repeated `--tag`, and `--reasoning-effort` before the corresponding `ALA_MODEL`, `ALA_TAGS`, and `ALA_REASONING_EFFORT` values. `--model-config` must set the resolved `LLM_MODELS_CONFIG_PATH` before AchillesAgentLib initializes. The runtime must retain MainAgent for the active interactive session, forward interruption to the active session, normalize the returned result, shut MainAgent down, and remove the discovery registry. These hidden lifecycle actions ensure that model choice reaches the executor, feedback reaches the same conversation, interruption reaches active work, and temporary discovery state does not survive the process. DS001 and DS002 define dependency and model-selection constraints.

Research access, general task-workspace requests, and [Ploinky](wiki.html#definition-ploinky) hosting remain specialized contracts in DS002, DS004, and DS005.

### Authenticated coding-agent delegation

A human, calling agent, or MainAgent-selected execution path may delegate a bounded complex request to an installed [coding agent](wiki.html#definition-coding-agent). `ala agent list` must report available Codex, OpenCode, Pi, and Claude Code executables in that fixed order without starting a model session. Interactive `/agent use <codex|opencode|pi|claude>` must save `codingAgent` as the default backend for later automatic selection. Interactive `/agent <name> models` must list identifiers from the selected backend's native catalog, `/agent <name> model <model-name>` must persist and immediately apply that backend's selection, and `/agent <name> model default` must delete the persisted override and immediately restore native agent-default selection. Both model commands clear that backend's configured effort. `--ca auto|codex|opencode|pi|claude` is the orchestration-facing selector and `--agent` remains its compatibility spelling. `auto` resumes a session's saved backend, otherwise selects the configured `codingAgent` when installed, otherwise the first available of Codex, OpenCode, Pi, Claude Code. `--session-id` without `--ca` behaves as `--ca auto`. `--model` replaces the selected backend's configured model for one invocation when coding-agent execution is selected.

Web search must always be enabled for Codex and OpenCode through their native controls and for Claude Code through its built-in `WebSearch` and `WebFetch` tools, and ALA must offer no option or command that disables it. Pi has no web search, and ALA must not add a third-party capability for it. ALA must not persist search credentials or bypass provider or source-site limits.

When at least one backend is detected, ALA must add its generic `coding-agent` Code Skill to the process-scoped discovery registry used by MainAgent. This internal skill is runtime infrastructure and is not a task skill. ALA mounts exactly the caller-supplied directories: the writable `--cwd <path> [as <alias>]` and each read-only `--folder <path> [as <alias>|at <absolute-path>] [expose]`, or read-write with `write`. Without an alias a directory is mounted at its canonical absolute path; an alias mounts it under `/workspace/<alias>`. When `--cwd` is omitted ALA creates and retains a private temporary workspace. An explicit `--home` supplies persistent backend configuration and authentication state. ALA preserves the backend's native continuation inside a session and never deletes a caller-supplied or temporary working directory. The installed backend and runtime are mounted read-only and are never installed into the mounted directories. ALA must validate and mount the supplied directories without interpreting their configuration or communication protocols, and it must not discover or prepare task skills or infer their mounts. Caller-supplied `--ignore` directories remain inaccessible behind empty read-only sandbox mounts, including ordinary aliases. Callers may explicitly overlay read-only directories and export selected subdirectories of ignored sources while retaining private parent masks. DS004 defines validation and visibility. DS002 and DS004 define backend and mount details.

## Conclusion

ALA fulfills its purpose by accepting single-shot and interactive requests and running work through configured AchillesAgentLib components or a detected authenticated coding agent against caller-owned mounts while preserving clean output and bounded lifecycle behavior.
