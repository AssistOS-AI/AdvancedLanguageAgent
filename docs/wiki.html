Advanced Language Agent Wiki

This page is the canonical reference for specialized project terminology. Each entry explains one concept and links only to different concepts needed to understand its relationships.

AchillesAgentLib

AchillesAgentLib is the external JavaScript library installed under the package identity ploinky-agent-lib. ALA uses it for skill discovery, MainAgent, LLMAgent, model tags, sessions, cancellation, and the execution subsystems associated with supported skill families.

ALA resolves the library from an explicit path, the ACHILLES_AGENT_LIB_PATH environment value, a sibling checkout, or the package dependency. Model providers and concrete model identifiers remain AchillesAgentLib configuration. ALA passes supported overrides to the library and does not reimplement provider credentials or model invocation.

Task skill (SKILL.md)

A task skill is an Anthropic-style declaration defined in SKILL.md inside an independently versioned task repository. The repository owner defines the methodology, required checks, and acceptance conditions.

A task skill owns domain procedure and is selected by name through --skill. It is not copied into ALA's core and may request model, agent, research, or workspace services from the runtime as part of its declared execution requirements.

Task repository

A task repository is an independently installed and versioned directory that packages one coherent family of specialized work and its task skills, each declared in SKILL.md. Operators register persistent repositories with ala repo add or supply them through ALA_TASK_REPOSITORIES and --task-repo.

ALA validates AchillesAgentLib skill descriptors, combines canonical repository paths, and rejects duplicate canonical skill names. Removing a registration changes only ALA's configuration and does not delete repository files. Task repositories are optional because general requests remain available with an empty catalog.

Skill catalog

The skill catalog is the set of enabled task skills that one ALA runtime presents to MainAgent. ALA builds it from persistent, environment-provided, and invocation-specific task repositories after canonical path deduplication and manifest validation.

The catalog may be empty. In that state MainAgent performs general model-backed execution and may still use generic runtime skills supplied by ALA. A populated task catalog permits automatic task skill selection, while --skill requests one named task entry explicitly.

Discovery registry

The discovery registry is a process-scoped temporary directory created by ALA to present multiple task-repository skills directories and available generic runtime skills to one MainAgent. It contains links to owning task repositories rather than copied task skill content.

ALA removes the registry when runtime creation fails or when execution closes. This arrangement lets independently owned repositories participate in one catalog without transferring ownership of their code or documentation to the ALA repository.

MainAgent

MainAgent is the AchillesAgentLib coordinator that ALA creates for each runtime. It receives the discovery-registry path, prepares available skills, retains the active conversation, and executes prompts through its configured LLMAgent and supported skill subsystems.

When no task skill is available or explicitly selected, MainAgent still executes a general request. ALA forwards cancellation to MainAgent and shuts it down before removing the temporary registry.

LLMAgent

LLMAgent is the AchillesAgentLib class through which ALA's model-backed work runs. It resolves an explicit model, semantic tags, reasoning effort, and configured defaults into an eligible provider invocation.

ALA supplies command-line or environment overrides but does not call providers outside LLMAgent. If no model is explicitly selected, AchillesAgentLib applies its configured defaults, which may point to Soul Gateway or another provider.

Generic execution capability

A generic execution capability describes how ALA can run work without embedding a domain-specific method. The architecture recognizes direct, fast, and deep model execution, authenticated coding-agent execution, multi-step agentic execution, web and research access, and temporary workspace creation.

A task skill may request these services while retaining ownership of its procedure and acceptance conditions. Availability depends on configured providers and installed executors; the capability name does not guarantee that every deployment supplies a matching backend.

Coding agent

A coding agent is a supported authenticated command-line agent that can plan, use tools, validate intermediate work, and return a final response for a bounded ALA request. The standalone runtime supports Codex, OpenCode, and Pi. Although these tools can edit code, ALA uses them as general executors for language, research, planning, verification, transformation, and bounded code-fragment tasks.

ALA detects their executables when each process starts and registers a generic Code Skill when at least one is available. The agent keeps ownership of its authentication and model configuration. ALA passes only the prompt and an ALA-created task workspace, retains the agent's opaque native continuation during an interactive session, and removes the workspace at shutdown. This generic runtime skill is not a task skill or a task-specific method.

Execution routing

Execution routing is the decision that maps a general request or selected task skill requirements to an eligible configured model, agent, research facility, or workspace service. It occurs after any task-method decision and must not change the selected method's domain procedure.

ALA forwards model, tag, and reasoning overrides to AchillesAgentLib. MainAgent owns concrete prompt and skill execution under the broader capability-based routing contract.

Symbolic routing

Symbolic routing is an experimental instruction-only task-selection path enabled inside an interactive session with /symbolic detection on. It extracts actions, objects, targets, modifiers, structural markers, and relationships, then compares that evidence with optional routing metadata in task-skill declarations supplied by task repositories.

The router permits direct execution only for deterministic or sufficiently strong high-confidence matches. Ambiguous and unknown requests use abstention and return to the default MainAgent path. /symbolic detection off disables the experimental path for the remainder of the session.

Abstention

Abstention is the symbolic router's decision not to force a task match when its instruction evidence is ambiguous or unknown. The request returns to the MainAgent-compatible default path so uncertainty does not select an unrelated specialized method.

The routing design treats a false confident selection as more harmful than abstention. Concrete confidence thresholds remain deployment configuration and are not fixed by the current CLI.

Agentic execution

Agentic execution is a bounded multi-step mode in which an eligible agent may plan, invoke tools, retry, validate, and synthesize a result. It is intended for work whose procedure cannot be completed adequately by one straightforward model call.

A task skill continues to own the task procedure and acceptance conditions. Retry limits and escalation policy must remain finite; ALA does not expose a separate command that directly selects this mode.

Task workspace

A task workspace is an isolated temporary directory for one multi-stage request. It may contain explicit input, retrieved sources, intermediate artifacts, verification results, and final output needed by a task skill or agentic execution path.

A task workspace is not an implicit copy of the caller's source repository and does not give ALA general ownership of that repository. A task skill may request one, while coding-agent execution creates one automatically. The public CLI does not accept a real project directory for coding-agent work, and the runtime removes its temporary workspace when execution closes.

Code Skill

A Code Skill in this documentation refers to ALA's core runtime skill for authenticated coding-agent delegation. It is not a task-skill and is not defined in a task repository.

ALA discovers the descriptor and delegates execution to AchillesAgentLib. The component that distributes the skill remains responsible for its module, contract, and verification rules. A generic core Code Skill does not become a task skill.

Orchestration Skill

An Orchestration Skill is a task-skill pattern that coordinates multiple capabilities, tools, or agents for a multi-step request.

ALA supplies the shared runtime and available executors, while the owning task repository defines the orchestration procedure, constraints, and completion checks.

DBTable Skill

A DBTable Skill is a task-skill pattern for workflows that include structured table data.

ALA treats these declarations as task skills and does not assume ownership of the referenced data model. The task repository remains responsible for its database contract and permitted operations.

Dynamic Code Generation Skill

A Dynamic Code Generation Skill is a task-skill pattern in which code is produced dynamically as part of task execution, while the repository-defined procedure remains the source of truth.

The task repository defines when generation is appropriate and which checks apply. ALA provides access to execution services but does not convert the skill into a core domain method.

Soul Gateway

Soul Gateway is an AchillesAgentLib model provider that can resolve semantic model names such as plan, fast, write, and deepSOUL_GATEWAY_BASE_URL and SOUL_GATEWAY_API_KEY.

AchillesAgentLib loads an applicable .env file by walking upward from the current working directory and preserves environment values that are already set. The bundled model configuration maps the default planning model to soul_gateway/plan; deployments may replace that configuration through LLM_MODELS_CONFIG_PATH.

Ploinky

Ploinky is an external agent-hosting environment described by ALA's integration contract. A deployment may expose ALA operations through Ploinky interfaces or use a Ploinky agent as an executor when its advertised capabilities match the request.

ALA remains a standalone CLI and must not require Ploinky. Concrete hosting and remote-agent protocols remain integration contracts outside the implemented standalone runtime.

WebChat

WebChat is the Ploinky browser conversation interface through which a hosted ALA agent may receive task requests. It is an optional integration surface and does not replace the standalone ala command.

The ALA repository defines the shared request and result contract but does not own WebChat transport. Ploinky owns authentication, session transport, and browser hosting behavior.

Routing evaluation

Routing evaluation compares explicit skill selection, MainAgent-compatible default selection, and experimental symbolic-first selection against one request corpus. It measures whether each path selects the expected method and ultimately produces the correct result.

The corpus includes canonical requests, paraphrases, multilingual input, spelling errors, ambiguity, multi-step work, missing parameters, and unsupported tasks. False confident symbolic selection receives a greater penalty than abstention because it bypasses the safe default path.
