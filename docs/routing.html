Task and A-Skill routing

Advanced Language Agent (ALA) uses AchillesAgentLib, a JavaScript library for discovering and running agent skills. An A-Skill is a reusable AchillesAgentLib skill that packages the instructions and optional code for one kind of task. Task routing selects the A-Skill that matches the caller's instruction. After that selection, execution routing chooses the model, agent, research tool, or workspace needed to run it.

How ALA selects an A-Skill

flowchart LR
      X[Instruction] --> E{Explicit selection?}
      E -->|yes| S[Selected A-Skill]
      E -->|no| Y{Symbolic mode enabled?}
      Y -->|no| M[MainAgent selection]
      Y -->|yes| C{Clear symbolic evidence?}
      C -->|yes| S
      C -->|no| M
      M --> S
      S --> Q[Execution requirements]

Explicit selection always wins. Without an explicit selection, AchillesAgentLib's MainAgent is the default selector: it compares the instruction with the registered skills and chooses the best match. Experimental symbolic-first mode may run before MainAgent. It examines only the instruction and falls back to MainAgent when its evidence is insufficient; it must not inspect the supplied payload to increase confidence.

The symbolic router identifies actions, objects, targets, modifiers, structural markers, and explicit relationships in the instruction. It returns DETERMINISTIC for an explicit or canonical match, HIGH when one candidate clearly dominates, AMBIGUOUS when several candidates remain, and UNKNOWN when its rules cannot explain the request. Only deterministic and sufficiently strong high-confidence matches execute directly. Ambiguous and unknown results go to MainAgent.

How routing is evaluated

Routing tests distinguish a correct direct selection, an incorrect direct selection, an abstention, a fallback to MainAgent, and the final result after fallback. A false confident selection is more harmful than abstention because it sends the request to the wrong A-Skill instead of asking the default selector to decide.
