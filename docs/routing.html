Documentation / Routing

Task and A-Skill routing

Routing chooses what work the instruction requests. Execution routing is a separate step that chooses how to perform that work.

Selection order

flowchart LR
  X[Instruction] --> E{Explicit task or skill?}
  E -->|yes| S[Selected A-Skill]
  E -->|no| M[Achilles MainAgent detection]
  E -->|symbolic mode| Y{Clear symbolic evidence?}
  Y -->|yes| S
  Y -->|no| M
  M --> S
  S --> Q[Execution requirements]

Explicit selection always wins. The default path remains compatible with AchillesAgentLib/MainAgent intent detection. Experimental symbolic-first mode examines only the instruction and may abstain; it must not inspect the payload to manufacture confidence.

Symbolic states

The symbolic router extracts actions, objects, targets, modifiers, structural markers, and explicit relationships. It returns DETERMINISTIC for explicit or canonical matches, HIGH when one candidate clearly dominates, AMBIGUOUS when multiple candidates remain, and UNKNOWN when rules cannot explain the request. Only deterministic and sufficiently strong high-confidence matches may execute directly. Ambiguous and unknown requests fall back to MainAgent.

Safety metric

Evaluation must distinguish correct direct routing, incorrect direct routing, abstention, fallback, and final correctness after fallback. A false confident route is materially worse than an abstention because it bypasses the established selector.
