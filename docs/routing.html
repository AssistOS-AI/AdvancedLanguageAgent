Documentation / Routing

Task selection and backend routing

ALA can execute a general request with an empty skill catalog. When an A-Skill is available, ALA first selects what specialized work must be performed, then selects how that work will run.

Selection precedence

--skill <name> selects an A-Skill explicitly and calls its AchillesAgentLib subsystem without intent classification. --agent <name> instead forces the generic coding-agent path, and the two explicit choices are mutually exclusive. Without either option, ALA passes the instruction to MainAgent. An empty task catalog produces general model-backed execution while a detected coding agent remains available as a generic runtime tool. The experimental symbolic routing path is disabled by default and is enabled for an interactive session with /symbolic detection on; off disables it again.

Task-selection detail

The task-method stage contains the precedence decisions hidden by the overview. Explicit choices bypass automatic selection; otherwise ALA uses MainAgent, with the optional symbolic path able to select a confident match first.

Symbolic-routing detail

When `/symbolic detection on` is active, the symbolic router makes a bounded decision from instruction evidence and A-Skill metadata. It does not inspect payloads. Only a clear result bypasses MainAgent.

Symbolic routing and abstention

When enabled, symbolic routing extracts actions, objects, targets, modifiers, structural markers, and explicit relationships from the instruction only. A task repository supplies optional ## Symbolic Routing metadata in an A-Skill descriptor, including characteristic phrases, required parameters, and conflicting evidence. Supplied payloads cannot increase routing confidence.

The result states are DETERMINISTIC, HIGH, AMBIGUOUS, and UNKNOWN. Deterministic and sufficiently strong high-confidence results may execute directly. Ambiguous and unknown results must use abstention and return the request to the MainAgent-compatible path. This policy treats a false confident match as more harmful than a safe fallback.

Execution routing

After task selection, execution routing maps the A-Skill's requirements to direct model execution, stronger reasoning, an authenticated agent, research access, multi-step execution, or an isolated workspace. Automatic coding-agent selection uses the available backend priority, defaulting to Codex, OpenCode, then Pi. The task repository continues to own the method and acceptance conditions.

Model and tag overrides use command-line values before ALA_MODEL, ALA_TAGS, and ALA_REASONING_EFFORT. Unknown explicit A-Skills and invalid repositories stop before execution with diagnostics on standard error.
