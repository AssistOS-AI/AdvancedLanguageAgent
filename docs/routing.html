Documentation / Routing

Task selection and backend routing

ALA can execute a general request with an empty skill catalog. When a task skill is available, ALA first selects what specialized work must be performed, then selects how that work will run.

Selection precedence

--skill <name> selects one Anthropic task skill explicitly and sends its instructions to the first available coding agent. --agent <name> forces the same generic agent path without selecting a task skill, and the two explicit choices are mutually exclusive. Any active --folder or interactive folder registration also forces coding-agent execution so filesystem context is never offered to MainAgent implicitly. Without an explicit or folder-forced route, a populated catalog is offered to a coding agent for selection; an empty catalog or unavailable coding agent leaves general model-backed execution with MainAgent. The experimental symbolic routing path is disabled by default and is enabled for an interactive session with /symbolic detection on; off disables it again.

Task-selection detail

The task-method stage contains the precedence decisions hidden by the overview. Explicit choices bypass automatic selection; otherwise the optional symbolic path may select a confident match before the coding agent receives the full catalog.

Symbolic-routing detail

When /symbolic detection on is active, the symbolic router makes a bounded decision from instruction evidence and task-skill metadata. It does not inspect payloads. Only a clear result bypasses coding-agent catalog selection.

Symbolic routing and abstention

When enabled, symbolic routing extracts actions, objects, targets, modifiers, structural markers, and explicit relationships from the instruction only. A task repository supplies optional ## Symbolic Routing metadata in task-skill definitions, including characteristic phrases, required parameters, and conflicting evidence. Supplied payloads cannot increase routing confidence.

The result states are DETERMINISTIC, HIGH, AMBIGUOUS, and UNKNOWN. Deterministic and sufficiently strong high-confidence results identify one skill before coding-agent execution. Ambiguous and unknown results must use abstention and let the coding agent inspect the full catalog. This policy treats a false confident match as more harmful than a safe fallback.

Execution routing

After task selection, execution routing chooses an available coding agent, defaulting to Codex, OpenCode, then Pi. ALA mounts the selected skill and its resources read-only in the Bubblewrap workspace and applies explicitly authorized folder mounts, while the task repository continues to own the method and acceptance conditions. Direct LLMAgent execution remains the path for general requests without a usable task catalog or active folder.

Model and tag overrides use command-line values before ALA_MODEL, ALA_TAGS, and ALA_REASONING_EFFORT. Unknown explicit task skills and invalid repositories stop before execution with diagnostics on standard error.
