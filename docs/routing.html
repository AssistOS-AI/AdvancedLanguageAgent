Documentation / Routing

Task selection and backend routing

ALA first selects what work must be performed, then selects how that work will run. Keeping those decisions separate lets an A-Skill retain the same method across provider and agent configurations.

Selection precedence

Explicit task or A-Skill selection always wins. Without an explicit choice, the default path uses the MainAgent-compatible selector. Experimental symbolic routing may run first, but it examines only the instruction; payload contents cannot increase its confidence.

Symbolic routing and abstention

Symbolic routing extracts actions, objects, targets, modifiers, structural markers, and explicit relationships between operations. A task repository may add characteristic phrases, required parameters, and conflicting evidence.

The result states are DETERMINISTIC, HIGH, AMBIGUOUS, and UNKNOWN. Deterministic and sufficiently strong high-confidence results may execute directly. Ambiguous and unknown results must use abstention and return the request to the MainAgent-compatible path. This policy treats a false confident match as more harmful than a safe fallback.

Execution routing

After task selection, execution routing maps the A-Skill's requirements to direct model execution, stronger reasoning, an authenticated agent, research access, multi-step execution, or an isolated workspace. The task repository continues to own the method and acceptance conditions.

Definitions

Symbolic routing
An optional instruction-only selection path that chooses a task directly only when symbolic evidence is sufficiently clear.
Abstention
A routing result that declines to select a candidate and transfers the request to the MainAgent-compatible path.
Execution routing
The post-selection decision that maps task requirements to an eligible configured model, agent, research facility, or workspace.
