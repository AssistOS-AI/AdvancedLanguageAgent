Documentation / Commands

ALA command reference

The ala executable lets a human or calling agent run one language request, retain an interactive conversation, or manage optional task repository registrations. General execution does not require a repository.

Execute a request

ala [options] [instruction...]

Positional words form the instruction. With no instruction in a terminal, ALA starts an interactive session. In a non-interactive pipeline with no positional instruction, standard input becomes the instruction. A populated Anthropic skill catalog is handled by a coding agent; otherwise the command sends the composed prompt to MainAgent. The normalized result is written to standard output unless --output selects a file.

ala "Summarize the report" --file report.md
printf 'Summarize this text' | ala
ala --interactive

Interactive slash commands

When an interactive session is active, a line beginning with / is handled locally before ALA calls MainAgent. These commands therefore do not consume an LLM prompt. While a terminal waits for a MainAgent or coding-agent response, ALA animates Thinking., Thinking.., and Thinking... on the diagnostic stream. The first supported coding-agent event clears the indicator and replaces it with live backend output; the normalized final answer remains on standard output. The indicator and live events are disabled when interactive input or diagnostic output is redirected.

CommandBehavior
/helpPrints the complete interactive command list and explains what each command does.
/agent listPrints only the names of detected backends, one per line.
/agent <name> modelsQueries the named Codex, OpenCode, or Pi backend and prints its native model identifiers, one per line.
/agent <name> model <model-name>Persists the model identifier for the named backend and applies it to every later invocation in the current and future sessions.
/agent <name> model defaultDeletes the named backend's persisted override and immediately returns subsequent invocations to the coding-agent CLI's own default model.
/agent auto <prompt>Delegates the prompt to the first available backend in configured priority order.
/agent codex <prompt>Delegates the prompt directly to Codex. OpenCode and Pi use the same form with their names.
/agent, /agent helpPrints the same complete interactive command list as /help.
/repo add <git-url>Clones and registers a Git task repository, then refreshes the active skill catalog. Local paths are rejected, and the next prompt in the same session can use the new skills.
/repo listPrints registered persistent task repository paths.
/repo remove <name>Removes a persistent registration by repository name without .git, then refreshes the active skill catalog before the next prompt. The registered path and Git URL remain supported, and TAB completes matching registered names.
/symbolic detection on|offEnables or disables the experimental instruction-only symbolic router for the remainder of the session. Uncertain matches let the coding agent select from a populated catalog; an empty catalog or unavailable coding agent falls back to MainAgent.
/websearch on|offPersists codingAgents.websearch in the selected configuration and immediately enables or disables web tools for subsequent coding-agent requests without resetting the workspace or native continuation.
/quit, /exitCloses the interactive session. The existing :quit and :exit aliases remain supported.

Execution options

OptionBehavior

--ca <name>Selects auto, codex, opencode, or pi. --agent remains a compatibility spelling. --model is forwarded as a native model hint for explicit coding-agent execution.

--output <path>Writes the result to the selected path instead of standard output.
--forceAllows --output to replace an existing file. Without this option, ALA refuses the overwrite.
--interactive, -iStarts or retains an interactive session. Enter :quit or :exit to close it.
--websearch [on|off]Bare --websearch enables coding-agent web search for this invocation. The explicit on or off value overrides the persistent setting for the invocation only. The option does not write the configuration file.
--home <path>Uses an existing directory as the coding-agent home and persistent configuration/account state.
--cwd <path>Uses an existing directory as the persistent writable workspace instead of creating a temporary directory.
--skillSets <a,b>Restricts the exposed read-only task-skill catalog to exact names.
--task <text> / --taskFile <path>Supplies an inline or file-backed task prompt.
--MCPServers <addresses>Injects comma-separated Streamable HTTP MCP URLs into Codex for this invocation only.
--model <value>Selects a configured model name or semantic model value for this invocation.
--tag <tag>Adds a model-selection tag. The option may be repeated, and command-line tags replace ALA_TAGS.
--reasoning-effort <value>Overrides the reasoning effort forwarded to AchillesAgentLib.
--model-config <path>Resolves the path from the current working directory and supplies it to AchillesAgentLib through LLM_MODELS_CONFIG_PATH.

--help, -hPrints usage and option help to standard output without starting the runtime.
--version, -vPrints the version from package.json to standard output.

Each file or URL payload is limited to 10 MiB, and all explicit payloads together are limited to 32 MiB. Diagnostics and interactive prompts use standard error so standard output remains usable by another program.

Add a task repository

ala repo add <git-url> [--config <path>] [--help]

This command rejects local paths and clones a Git URL into $XDG_DATA_HOME/ala/repositories, with ~/.local/share/ala/repositories as the fallback. It removes the clone's origin remote so a credential-bearing URL is not retained, recursively discovers Anthropic SKILL.md descriptors with valid name and description frontmatter, stores the managed local path in the selected ALA configuration, and prints that path. It does not search for AchillesAgentLib skill descriptors. Adding the same Git URL again is idempotent and does not update an existing clone. ALA_TASK_REPOSITORIES supplies platform-delimited local repository paths through the environment.

List task repositories

ala repo list [--config <path>] [--json] [--help]

This command prints persistent repository paths from the selected configuration. The default output contains one path per line. --json writes a JSON array, including an empty array when no repository is registered.

Remove a task repository

ala repo remove <name-or-path-or-git-url> [--config <path>] [--help]

This command removes the matching repository name, canonical path, lexical path, or managed Git URL path from ALA configuration and prints the removed path. The short name is the final Git URL component without .git; for example, https://github.com/example/claude-skills.git is removed with ala repo remove claude-skills. If more than one registration has the same short name, ALA reports ambiguity and requires the registered path or Git URL. Removal does not delete the task repository, including a clone created by ALA. An unregistered source produces repository exit code 4.

In an interactive terminal, TAB completion is available for /repo remove . A partial name such as /repo remove clau completes or lists matching names from the current persistent configuration, and the candidates update after each successful interactive addition or removal.

Inside an interactive session, an addition or removal reloads all active repository sources immediately. Reloading changes only the strict read-only skill bind mounts used by the next coding-agent process and preserves workspace files, selected backend, native continuation, MainAgent conversation, symbolic-detection state, and web-search state. If the combined catalog or mount preparation cannot be validated, ALA restores the previous repository registration and leaves the active catalog and mount set unchanged.

Each repository command accepts --help and prints the common command reference without reading or changing configuration.

List coding agents

ala agent list [--config <path>] [--json] [--help]

This command detects Codex, OpenCode, and Pi without starting AchillesAgentLib or an LLM session. Text output prints only the names of available backends, one per line. --json returns an ordered JSON array containing those names. Empty output or an empty array means that no supported backend was detected.

Coding-agent sandbox and workspace

Every Codex, OpenCode, or Pi execution and model-catalog query runs through Linux Bubblewrap. ALA uses the backend already installed on the host and mounts its resolved launcher and runtime prefix read-only; it never reinstalls an agent in the temporary workspace. ALA exposes that workspace read-write at /workspace, mounts task skills strictly read-only under /workspace/.agents/skills, clears inherited environment variables before restoring a backend-specific allowlist, isolates temporary and home directories, keeps unrelated host paths absent, and shares networking for provider and enabled search access. A functioning bwrap is mandatory; failure produces exit code 5 and never falls back to an unsandboxed process.

An explicit --cwd is the sole caller-provided writable project tree and persists after ALA exits. Without it, ALA owns a temporary workspace and deletes that workspace at shutdown. Arbitrary additional host-folder mounts are rejected.

Symbolic detection

Symbolic detection is disabled by default and is enabled only inside an interactive session with /symbolic detection on. It examines the instruction, never payload contents, and compares its extracted evidence with the optional ## Symbolic Routing metadata section in each task skill definition. The section accepts comma-separated actions, objects, targets, modifiers, phrases, required, and conflicts values.

A confident DETERMINISTIC or HIGH match sends the selected task skill to the coding agent. AMBIGUOUS and UNKNOWN results abstain from deterministic selection and let the coding agent choose from the full catalog. Explicit --skill and --agent selections always take precedence.

Configuration precedence

The ALA configuration file resolves in this order: an explicit --config <file>; <ALA_CONFIG_PATH>/.ala/config.json when the environment variable names a root directory; then $HOME/.ala/config.json. ALA_TASK_REPOSITORIES adds platform-delimited repository paths after persistent configuration, with canonical-path deduplication. Direct LLMAgent model selection resolves command-line values before ALA_MODEL, ALA_TAGS, and ALA_REASONING_EFFORT, after which AchillesAgentLib applies its configured defaults.

ALA persists no execution history. Embedding applications may opt into structured public progress with ALA_EVENT_STREAM=1 and combine it with the standard-output result in caller-owned storage. One-shot callers must supply any desired prior conversation again.

Coding-agent executable resolution checks CODEX_BIN, OPENCODE_BIN, or PI_BIN first, followed by the backend's standard user installation path and PATH. The optional codingAgents.priority configuration array defaults to ["codex", "opencode", "pi"]; ALA_CODING_AGENT_PRIORITY supplies a comma-separated environment override. The optional codingAgents.models object maps a backend name to its selected native model identifier. The Boolean codingAgents.websearch setting defaults to false, and an explicit --websearch value has invocation-only precedence over it. Codex listing uses app-server model/list, OpenCode uses opencode models, and Pi uses pi --list-models with its provider and model columns normalized to provider/model.

When enabled, ALA starts Codex with native live search and grants OpenCode's websearch and webfetch tools in the temporary workspace while opting into its Exa search integration. When disabled, ALA explicitly disables or denies those tools. Pi has no ALA-managed web-search capability, and ALA neither adds an extension nor changes Pi's tools for this setting. This controls supported agent tools, not provider credentials or site access policy; the selected CLI and search provider still own authentication, quotas, rate limits, and compliance with source terms.

For Soul Gateway, set SOUL_GATEWAY_BASE_URL and SOUL_GATEWAY_API_KEY in the process environment or in the first .env file AchillesAgentLib finds while walking upward from the current working directory. Use LLM_MODELS_CONFIG_PATH or --model-config to supply another model catalog.

Exit codes

CodeMeaning
0The command completed successfully.
2An option, command, or configuration value was invalid.
3ALA could not read an input or safely write the requested output.
4A task repository, task skill, or AchillesAgentLib dependency could not be resolved or validated.
5Runtime execution failed.
130The active execution was interrupted.
