Documentation / Commands

ALA command reference

The ala executable lets a human or calling agent run one language request, retain an interactive conversation, or delegate to a detected coding agent against caller-owned mounts.

Execute a request

ala [options] [instruction...]

Positional words form the instruction. With no instruction in a terminal, ALA starts an interactive session. In a non-interactive pipeline with no positional instruction, standard input becomes the instruction. Explicit coding-agent selection runs the request through the detected backend; otherwise the command sends the composed prompt to MainAgent. The normalized result is written to standard output unless --output selects a file.

ala "Summarize the report" --file report.md
printf 'Summarize this text' | ala
ala --ca codex --cwd /project --folder /shared "Inspect the project"

Mounts and working directories

ALA mounts exactly the directories the caller supplies and never discovers, creates, mounts or overlays task skills. --cwd <path> [as <alias>] is the writable working directory: without an alias it is mounted at its canonical absolute path, with an alias at /workspace/<alias>. When --cwd is omitted ALA creates and retains a private temporary directory. Each --folder <path> [write] [as <alias>] is read-only unless marked write. A read-only ancestor may contain the writable cwd; ancestors are mounted before descendants. Overlapping or duplicate destinations and reserved sandbox paths are rejected.

Persistent coding-agent sessions

--session-id <uuid> creates a persistent conversation and requires explicit --home and --cwd in one-shot mode. Omitting --ca is the same as --ca auto. --home holds the coding agent's native state and configuration. ALA itself keeps the conversation in an append-only session transcript at $ALA_SESSIONS/sessions/<uuid>.jsonl. When ALA_SESSIONS is unset, the directory is <cwd>/.ala; a relative value resolves against --cwd. Add --resume-session to resume that exact conversation from the last continuation recorded in the transcript. The backend chosen on first execution remains pinned. A missing transcript, a transcript without a native continuation, or another active process makes --resume-session fail. A session whose earlier turn failed before the coding agent started has no continuation, and the next call continues it without --resume-session. Once a session has a continuation, a call without --resume-session fails instead of starting a second conversation. Without --session-id, one-shot execution remains independent and writes no transcript.

ala --home /robots/analyst/home --cwd /projects/app --ca auto \
  --session-id 11111111-1111-4111-8111-111111111111 --task "Inspect the project"
ala --home /robots/analyst/home --cwd /projects/app --ca auto \
  --session-id 11111111-1111-4111-8111-111111111111 --resume-session --task "Continue."

--turn-id <id> sets the identifier written on every record of the turn. It accepts 1 to 128 characters from A-Z, a-z, 0-9, _, and -; without it ALA generates a random UUID. --resume-session, --control-stdin, and --turn-id each require --session-id; supplying one without it is a usage error with exit code 2.

Session transcript records

Each transcript line is one JSON object with seq, type, and an ISO at timestamp. Records that belong to a turn also carry turnId. ALA appends lines and never rewrites them. A reader ignores a trailing line that has no newline, because it is an interrupted append; any other malformed line is an error.

TypeFields and meaning
sessionFirst line of the file. id is the session UUID.
usertext is the user message: the task prompt for the turn, or the displayText of the control prompt record when present, then one record per accepted --control-stdin message.
agent-messageVisible coding-agent output buffered per output stream. outputKind is assistant or output, outputId is present when the backend supplies one, text holds the buffered text, and complete is true when the backend marked the output finished.
toolAn AchillesAgentLib tool call with tool and reason.
finaltext is the result written to standard output or --output.
turn-endstatus is completed, failed, or interrupted, with durationMs and, after a failure or interruption, error.
continuationThe pinned backend in agent and its opaque native continuation. The last one in the file wins.

A <uuid>.jsonl.lock file next to the transcript holds the host name, process ID, and process start time of the running ALA process. ALA replaces a lock left by a dead process on the same host. A lock written on another host is never treated as stale and blocks the session until it is removed. Pi keeps its own native session files in <workspace>/.ala-pi-sessions.

Embedding applications read transcripts through the advanced-language-agent/transcript package export rather than parsing files. Every reader takes the sessions directory, the value ALA resolves from ALA_SESSIONS or <cwd>/.ala. listSessions returns id, createdAt, updatedAt, and title for each session, newest first, with the first user message as the title. readSession returns the folded session with agent, continuation, and turns; readTurn returns one turn by turnId; readSessionSummary reads only the beginning of one file. sessionTranscriptPath, readTranscriptRecords, and foldTranscript expose the path, the raw records, and the folding step. Each reader also has a synchronous Sync variant.

Control stdin

With --control-stdin and no task argument, --task, --taskFile, or payload source, the first control record carries the turn prompt: {"type":"prompt","prompt":"Text for the coding agent","displayText":"The user's own text"}. ALA opens the session and the runtime, emits session-ready, and starts the coding agent only when this record arrives. The coding agent receives prompt. The transcript's user record holds displayText, or prompt when displayText is absent, so a host can wrap the user's words in its own instructions and still show what the user typed. prompt must be non-empty, and both fields are limited to 1 MiB (1048576 characters). ALA rejects any other record sent first with a message-rejected event reading "The first control record must be a valid turn prompt." and keeps waiting. If the control channel closes or the execution is cancelled before the prompt arrives, the coding agent never starts and ALA exits with an error.

printf '%s\n' '{"type":"prompt","prompt":"Follow the team rules. User request: fix the login test","displayText":"fix the login test"}' | \
  ala --home /robots/analyst/home --cwd /projects/app \
  --session-id 11111111-1111-4111-8111-111111111111 --control-stdin

When a task argument or file supplies the prompt, stdin carries only follow-up messages and interaction responses. --control-stdin cannot be combined with a --stdin payload. A control record may hold up to 2 MiB (2097152 characters); a longer line is rejected with "Input record too large." and discarded.

After the prompt, the host sends follow-up records such as {"type":"message","id":"request-1","message":"Also check the tests"} while the task executes. An optional displayText replaces message in the transcript's user record; the agent still receives message. Both message and displayText are limited to 32768 characters. Persistent mode emits @@ALA_EVENT@@ records on stderr, including session-ready, message-accepted with delivery set to delivered or queued, and message-rejected. stdout remains the final result. Codex uses app-server steering and Pi uses RPC steering. OpenCode follow-ups run sequentially after the active invocation. Queues belong to the live execution; interruption cancels pending follow-ups.

Native permissions and interactive replies

For Codex app-server execution, coding-agent-message carries complete intermediate messages or completed command output, not token deltas. Final-answer text is delivered through coding-agent-final and stdout rather than duplicated as progress. A direct answer can have no intermediate messages.

OpenCode final responses include all text parts of the completed final assistant message, with surrounding whitespace trimmed. The diagnostic tail limit does not apply to this final response, so structured answers retain their complete contents.

--permissions ask-for-approval|full-access selects native coding-agent policy for the execution. The default is full-access, still inside Bubblewrap. Pi supports full-access only; selecting ask-for-approval fails before model execution instead of changing backend or policy. Native policy may allow trusted operations or deny managed operations without a prompt.

A control-capable host receives coding-agent-request events containing an opaque id, backend agent, permission method, display title, message, detail, and options with opaque IDs, labels and descriptions. Send {"type":"interaction-response","id":"request-uuid","optionId":"advertised-option"} or {"type":"interaction-response","id":"request-uuid","cancelled":true} immediately on control stdin. Responses are not prompts. Invalid, stale or duplicate replies produce diagnostics; they cannot answer another request.

coding-agent-request-resolved closes the matching prompt with reason answered, cancelled, expired, or backend-resolved. Control EOF, interruption and backend failure cancel pending requests and the owned operation. Without a reply-capable control channel, an operation requiring approval is declined with an explicit diagnostic. ALA keeps no approval cache; native session grants need not survive recreation of the native process.

Codex app-server policy requests use untrusted in ask mode and never in full-access, with native sandbox disabled inside ALA's Bubblewrap boundary. Native command/file decisions and requested permission profiles keep their exact scope. OpenCode requires the compatible unprefixed session/permission server API evidenced by v1.15.10; ALA checks the executable and served API before prompting, uses one authenticated server per execution, and leaves project configuration files unchanged. Pi requires 0.85.1 or a verified compatible release; Pi 0.85.1 requires Node.js 22.19.0 or newer. Select a supported installation through PI_BIN rather than expecting ALA to update it.

Interactive slash commands

/permissions reports the requested native policy. /permissions ask-for-approval and /permissions full-access change it for subsequent executions in the same interactive runtime, without resetting the backend or conversation. The initial value comes from --permissions, defaulting to full-access. This command does not persist configuration or create an approval-response channel. Without a reply-capable host, operations requiring approval are declined; Pi rejects ask-for-approval.

When an interactive session is active, a line beginning with / is handled locally before ALA calls MainAgent. These commands therefore do not consume an LLM prompt. While a terminal waits for a MainAgent or coding-agent response, ALA animates Thinking., Thinking.., and Thinking... on the diagnostic stream. The first supported coding-agent event clears the indicator and replaces it with live backend output; the normalized final answer remains on standard output. The indicator and live events are disabled when interactive input or diagnostic output is redirected.

Each file or URL payload is limited to 10 MiB, and all explicit payloads together are limited to 32 MiB. Diagnostics and interactive prompts use standard error so standard output remains usable by another program.

List coding agents

ala agent list [--json] [--help]

This command detects Codex, OpenCode, and Pi without starting AchillesAgentLib or an LLM session. It does not read the configuration. Text output prints only the names of available backends, one per line, in the fixed order Codex, OpenCode, Pi. --json returns a JSON array of those names in the same order. Empty output or an empty array means that no supported backend was detected.

Coding-agent sandbox and workspace

Every Codex, OpenCode, or Pi execution and model-catalog query runs through Linux Bubblewrap. ALA uses the backend already installed on the host and mounts its resolved launcher and runtime prefix read-only; it never reinstalls an agent. ALA mounts the caller's writable --cwd and read-only --folder mounts at their canonical or aliased paths, clears inherited environment variables before restoring a backend-specific allowlist, isolates temporary and home directories, keeps unrelated host paths absent, and shares networking for provider and web-search access. A functioning bwrap is mandatory; failure produces exit code 5 and never falls back to an unsandboxed process.

An explicit --cwd is the caller-provided writable working tree and persists after ALA exits. Without it, ALA owns a temporary workspace and retains it at shutdown. Additional directories use explicit --folder mounts, read-only unless marked write.

Configuration precedence

The ALA configuration file resolves in this order: an explicit --config <file>; <ALA_CONFIG_PATH>/.ala/config.json when the environment variable names a root directory; then $HOME/.ala/config.json. A missing file is an empty configuration. Direct LLMAgent model selection resolves command-line values before ALA_MODEL, ALA_TAGS, and ALA_REASONING_EFFORT, after which AchillesAgentLib applies its configured defaults.

ALA_SESSIONS names the directory that holds session transcripts under its sessions/ child. A relative value resolves against --cwd, and an unset or empty value selects <cwd>/.ala. It does not affect configuration resolution. ALA records history only for --session-id executions. Other callers may opt into structured public progress with ALA_EVENT_STREAM=1 and keep it with the standard-output result in their own storage. One-shot callers without a session must supply any prior conversation again.

The configuration file is a JSON object with three optional fields: codingAgent names the default backend (codex, opencode, or pi), models maps a backend name to its native model identifier, and efforts maps a backend that has a configured model to a native effort name. ALA rejects any other field with exit code 2 and the message ALA configuration supports only codingAgent, models and efforts. It has no version field and reads no older layout.

{
  "codingAgent": "codex",
  "models": { "codex": "gpt-5.6-sol" },
  "efforts": { "codex": "high" }
}

Coding-agent executable resolution checks CODEX_BIN, OPENCODE_BIN, or PI_BIN first, followed by the backend's standard user installation path and PATH. Backend choice resolves in this order: an explicit --ca name; for auto, the backend saved in a resumed session; the configured codingAgent when it is installed; then the first available backend in the fixed order Codex, OpenCode, Pi. The order cannot be configured. Codex listing uses app-server model/list, OpenCode uses opencode models, and Pi uses pi --list-models with its provider and model columns normalized to provider/model.

Web search is always on. ALA starts Codex with --search, or web_search="live" for the app-server, and starts OpenCode with OPENCODE_ENABLE_EXA=1 and its websearch and webfetch tools allowed. Pi has no web search, and ALA adds none. There is no option or interactive command to turn search off. The selected CLI and its search provider still own authentication, quotas, rate limits, and compliance with source terms.

For Soul Gateway, set SOUL_GATEWAY_BASE_URL and SOUL_GATEWAY_API_KEY in the process environment or in the first .env file AchillesAgentLib finds while walking upward from the current working directory. Use LLM_MODELS_CONFIG_PATH or --model-config to supply another model catalog.

Exit codes

CodeMeaning
0The command completed successfully.
2An option, command, or configuration value was invalid.
3ALA could not read an input or safely write the requested output.
4An AchillesAgentLib or repository dependency could not be resolved or validated.
5Runtime execution failed.
130The active execution was interrupted.

Coding-agent reasoning effort is stored beside the model map as efforts, keyed by backend, in .ala/config.json. Each effort requires an explicit model. Native catalog metadata defines valid values: Codex supportedReasoningEfforts, Pi reasoning and thinkingLevelMap, and connected OpenCode model variants. Unsupported values fail before a model turn. Codex exec receives model_reasoning_effort, Codex app-server receives turn/start.effort, Pi receives --thinking, and OpenCode receives prompt_async.variant. These values apply to new and resumed executions; omitted values preserve native defaults. Changing or clearing a model clears its effort override. Direct LLMAgent --reasoning-effort remains separate.

Structured output provenance

Structured coding-agent-message events identify assistant text with outputKind="assistant" and other visible output with outputKind="output". Streaming assistant messages carry outputId when available; outputComplete marks a completed message and may accompany an empty message. Consumers can use these fields to distinguish assistant output from tool output and diagnostics without parsing visible text. ALA does not interpret or persist consumer-specific markers.

Ignored directories

Repeat --ignore /absolute/directory to mask existing directories with empty read-only mounts inside the coding-agent sandbox. Directory names remain visible; host data stays intact. Masks apply to canonical paths, aliases and mounts of ignored descendants. Missing, invalid or unmounted directories and masks covering the working directory fail before the backend starts. Repeat the option on resume. Supplying this option selects coding-agent execution.
