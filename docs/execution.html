Documentation / Execution

Execution backends, workspaces, and feedback

ALA executes general requests without requiring a task skill. When routing selects a task skill, ALA chooses an executor that can meet its quality and capability requirements while the task method remains independent from a provider or authenticated tool.

Generic execution capabilities

Straightforward work normally uses direct model execution through LLMAgent. The complete set of generic execution capabilities separates execution methods from domain procedures. Cost and latency may be optimized only among executors considered capable of meeting the task skill's requirements.

CapabilityExecution responsibility
Direct LLMRuns a prompt through the configured LLMAgent.
Fast LLMPrefers an eligible low-latency, lower-cost model for sufficiently simple work.
Deep LLMUses an eligible stronger model when task quality requires deeper reasoning.
Coding agentDelegates bounded work to a detected and authenticated Codex, OpenCode, or Pi CLI.
Agentic executionCoordinates multi-step planning, retries, validation, or synthesis.
Web and research accessRetrieves and checks external material when the task method requires it.
Temporary task workspaceIsolates inputs, intermediate artifacts, checks, and final outputs for one request.

At process startup ALA checks backend-specific binary overrides, standard user installation locations, and PATH. When it finds Codex, OpenCode, or Pi, it registers a generic AchillesAgentLib Code Skill that MainAgent can select. --agent forces the same skill without task intent classification. ALA invokes supported CLI interfaces and does not extract credentials, so a subscription-backed agent can execute work when no direct provider API key is configured.

Request input and result delivery

The positional text is the instruction. Repeated --text, --file, --url, and --stdin options add labeled payloads in argument order. Files and HTTP(S) responses are decoded as UTF-8, each file or response is limited to 10 MiB, the combined payload is limited to 32 MiB, and URL retrieval has a 30-second timeout.

In a non-interactive pipeline without a positional instruction, standard input becomes the instruction. With a positional instruction, standard input is read only when --stdin is present. The result is written to standard output or the file selected by --output; an existing file requires --force. Prompts and diagnostics remain on standard error.

Task workspaces and feedback

A task skill may request a task workspace for explicit input, retrieved sources, intermediate artifacts, verification results, and final output. Coding-agent execution always creates its own private temporary workspace and never receives the caller's working directory as its project directory. The task workspace is not an implicit copy of the caller's repository.

Running ala without an instruction in a terminal or using --interactive starts an interactive session. MainAgent retains its conversation across prompts. With explicit --skill selection, the runtime retains the selected method and supplies the previous result with corrective feedback. With explicit coding-agent execution, ALA retains the agent's native continuation identifier, pins the conversation to that backend, and reuses its temporary workspace until the session closes. :quit and :exit close the session and remove temporary state.

Configuration discipline

Every direct model call uses LLMAgent with AchillesAgentLib-compatible model tags. --model, repeated --tag, --reasoning-effort, and --model-config take precedence over environment-derived defaults. Documentation, specification, orchestration, bootstrap, and testing work can supply applicable metadata tags. DS002 contains the authoritative execution strategy.
