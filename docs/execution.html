Execution backends and task feedback

Advanced Language Agent (ALA) uses AchillesAgentLib, a JavaScript library for discovering and running agent skills. An A-Skill is a reusable AchillesAgentLib skill containing the instructions and optional code for one kind of task. After routing selects an A-Skill, that skill tells ALA which services the task needs, such as a fast large language model (LLM), stronger reasoning, long-context processing, web research, or a coding agent. ALA chooses a configured model or agent that provides those services.

How ALA chooses an executor

Direct LLM calls are the normal path for straightforward work. Complex planning, multi-source research, long transformations, iterative verification, and quality-sensitive synthesis may use stronger models or authenticated coding agents such as Codex or OpenCode. ALA invokes their command-line interfaces (CLIs) without reading or extracting their credentials. A Ploinky agent is a remotely invokable agent registered with the Ploinky router; ALA may use one when its advertised operations match the task requirements.

Workspace and feedback flow

flowchart LR
      A[Instruction and input]
      B[Select A-Skill and executor]
      C[Run and verify the task]
      D[Return the result]
      E{Feedback?}
      F[Task complete]
      G[Apply feedback and choose retry strength]

      A --> B --> C --> D --> E
      E -->|No| F
      E -->|Yes| G --> C

An A-Skill may request a temporary workspace for a task with several stages. The workspace may hold explicit inputs, retrieved sources, intermediate outputs, verification results, and final artifacts. It is not an implicit copy of the caller's software repository. Interactive sessions preserve the selected task and previous answer so corrective feedback can constrain the next attempt. Retries are bounded and may escalate from a fast model to a stronger model or from one model call to a multi-step agent run.
