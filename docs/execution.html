Documentation / Execution

Execution backends, workspaces, and feedback

ALA executes general requests without requiring a task skill. When routing selects an Anthropic task skill, ALA executes it through an authenticated coding agent while the task repository retains ownership of the method.

Generic execution capabilities

Straightforward general work normally uses direct model execution through LLMAgent. Anthropic task-skill execution uses a detected coding agent, which may apply tools, research, planning, and verification inside its isolated workspace while following the selected SKILL.md.

CapabilityExecution responsibility
Direct LLMRuns a prompt through the configured LLMAgent.
Fast LLMPrefers an eligible low-latency, lower-cost model for sufficiently simple work.
Deep LLMUses an eligible stronger model when task quality requires deeper reasoning.

Temporary task workspaceIsolates inputs, intermediate artifacts, checks, and final outputs for one request.

At process startup ALA checks backend-specific binary overrides, standard user installation locations, and PATH. When it finds Codex, OpenCode, or Pi, it registers a generic AchillesAgentLib Code Skill that bridges MainAgent to the native agent CLI. The existing launcher is resolved to its interpreter or package prefix and mounted read-only for execution; ALA does not install another copy in a task workspace. --agent forces this bridge without task selection, --skill supplies one selected Anthropic descriptor, and any active folder also forces the coding-agent route. Interactive commands can query each CLI's native model catalog and persist one model identifier per backend. ALA passes a configured identifier with the backend's native model option on every invocation, including continuation; without one, it omits the option so the CLI uses its own default. ALA does not extract credentials, so a subscription-backed agent can execute work when no direct provider API key is configured.

Web search is a coding-agent execution setting and is disabled by default. Bare --websearch enables it for one process, --websearch on|off supplies an explicit invocation override, and interactive /websearch on|off atomically saves the Boolean value and updates the existing coding-agent service without clearing its workspace or continuation. ALA uses Codex's native live-search flag and temporary OpenCode web-tool permissions plus its Exa opt-in. Pi has no ALA-managed web-search capability, so ALA leaves Pi arguments and tools unchanged in both states.

Request input and result delivery

The positional text is the instruction. Repeated --text, --file, --url, and --stdin options add labeled payloads in argument order. Files and HTTP(S) responses are decoded as UTF-8, each file or response is limited to 10 MiB, the combined payload is limited to 32 MiB, and URL retrieval has a 30-second timeout.

In a non-interactive pipeline without a positional instruction, standard input becomes the instruction. With a positional instruction, standard input is read only when --stdin is present. The result is written to standard output or the file selected by --output; an existing file requires --force. Prompts and diagnostics remain on standard error.

Task workspaces and feedback

Coding-agent execution always creates a private temporary workspace and never receives the caller's working directory as its project directory. Every backend execution and model-catalog process runs through Bubblewrap with that directory bound read-write at /workspace. The sandbox clears its inherited environment, remounts its root read-only, exposes system files and the selected existing backend runtime read-only, isolates temporary and home paths, and mounts only controlled backend authentication/state paths read-write. Codex receives its controlled home, Pi receives only .pi/agent plus its task session directory, and OpenCode receives only its configuration, cache, data, and state directories. The complete host home, host root, unrelated directories, and unrelated environment secrets are absent. ALA fails with execution code 5 if Bubblewrap is unavailable or cannot create the namespace.

ALA mounts every discovered Anthropic skill directory strictly read-only under /workspace/.agents/skills. Repeatable --folder <path> [write|w] values authorize additional canonical sources under /workspace/.ala/folders; read-only is the default, and exact write or w grants read-write access subject to host permissions. The generated /workspace/.ala/folders.json records aliases and access modes. Folder mounts are not persistent configuration and force the coding-agent route while active. The selected backend runtime is mounted read-only and preferred in the sandbox path. ALA probes procfs with the same dynamic runtime mounts used by execution, uses a private procfs where permitted, and otherwise leaves /proc empty; it never exposes the host procfs. Codex and OpenCode fail closed on hosts that genuinely block the private procfs they require. Networking remains shared, and when systemd-resolved places the target of /etc/resolv.conf under /run, ALA mounts only that resolver file read-only so DNS works without exposing the rest of the runtime tree.

Running ala without an instruction in a terminal or using --interactive starts an interactive session. While a terminal waits for MainAgent or coding-agent execution, ALA cycles a three-frame Thinking indicator on standard error. The first supported coding-agent event stops and erases that indicator; Codex intermediate assistant and command events, Pi assistant deltas and deduplicated tool text, or OpenCode native output then appear on the diagnostic stream while the normalized final answer remains the standard-output result. Codex's last completed assistant event is reserved for that final result instead of being rendered twice, and benign stdin or stale-rollout catalog diagnostics are suppressed on successful turns. The indicator and live events do not run when interactive input or standard error is not a terminal, which preserves redirected and machine-readable output. /help lists every local command and its behavior without sending a prompt to an LLM. Local /repo commands rebuild the read-only task-skill mount set, while /folder add, /folder list, and /folder remove manage the active session mount set. MainAgent retains its conversation, and repository or folder updates preserve workspace files, selected backend, native continuation, symbolic-detection state, and web-search state. With explicit --skill selection, the runtime retains the selected method while it remains present and supplies the previous result with corrective feedback. :quit and :exit close the session and remove temporary state.

Configuration discipline

Every direct model call uses LLMAgent with AchillesAgentLib-compatible model tags. --model, repeated --tag, --reasoning-effort, and --model-config take precedence over environment-derived defaults for direct execution only; they do not select or override a Codex, OpenCode, or Pi model. Coding-agent selection is independent and is changed only with /agent <name> model <model-name>. Documentation, specification, orchestration, bootstrap, and testing work can supply applicable metadata tags. DS002 contains the authoritative execution strategy.
