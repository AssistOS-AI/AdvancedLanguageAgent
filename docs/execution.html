Documentation / Execution

Execution backends and task feedback

After an A-Skill is selected, ALA resolves the capabilities it needs against the current environment. The skill requests a class of executor, such as a fast LLM, strong reasoning, long context, web research, or coding-agent execution; ALA chooses a configured compatible backend.

Backend policy

Direct LLM calls are the normal path for straightforward work. Complex planning, multi-source research, long transformations, iterative verification, and quality-sensitive synthesis may use stronger models or authenticated coding agents such as Codex or OpenCode. ALA invokes supported CLIs without reading or extracting their credentials. Ploinky agents may participate when their advertised capability metadata matches.

Workspace and feedback flow

sequenceDiagram
  participant C as Caller
  participant A as ALA
  participant S as A-Skill
  participant X as Executor
  C->>A: instruction and payload
  A->>S: select task method
  S->>A: capability and workspace requirements
  A->>X: execute bounded task
  X-->>A: result and checks
  A-->>C: result; diagnostics separate
  C->>A: corrective feedback (optional)
  A->>X: bounded retry or escalation

A temporary workspace may hold explicit inputs, retrieved sources, intermediate outputs, verification results, and final artifacts. It is not an implicit copy of the caller's software repository. Interactive sessions preserve the current task and previous answer; feedback becomes an additional constraint. Retries are bounded and may escalate from a fast model to a stronger model or from direct execution to agentic execution.
