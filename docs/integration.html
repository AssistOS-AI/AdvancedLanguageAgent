Documentation / Integration

Integration and evaluation

ALA operates as a standalone CLI and, where deployed, as a Ploinky agent. The same interface is exposed through existing Ploinky CLI and WebChat mechanisms.

Configuration boundary

Task repositories are configured independently from the ALA installation. Existing AchillesAgentLib model configuration and semantic tags are reused when available, including tags for fast, deep, planning, coding, research, and long-context work. Distribution metadata supplies the ALA manifest, configuration file, executable name, and provider installation procedure.

Evaluation paths

The evaluation corpus must compare explicit task selection, default Achilles/MainAgent detection, and symbolic-first detection. It must include canonical instructions, paraphrases, multilingual requests, spelling errors, ambiguous and multi-step requests, missing parameters, and unsupported tasks. Results must report direct-routing accuracy, incorrect direct routing, abstention, fallback, and final correctness after fallback.

Operational contract

Deployments must preserve the integration and evaluation contract recorded in DS005, including independent task-repository configuration, bounded retries, and measurable routing safety.
