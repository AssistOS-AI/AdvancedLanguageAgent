Documentation / Integration

Ploinky integration and routing evaluation

ALA operates as a standalone CLI and may also run as a Ploinky agent. Both forms preserve the same task-selection and result-separation contracts.

Deployment and configuration

The npm package exposes the ala executable and declares AchillesAgentLib as the Git dependency ploinky-agent-lib in package.json. User configuration resolves from --config, ALA_CONFIG_PATH, $XDG_CONFIG_HOME/ala/config.json, or ~/.config/ala/config.json. ala repo add, ala repo remove, and ala repo list manage persistent task repositories.

ALA reuses AchillesAgentLib model configuration and tags when present. CLI model, tag, reasoning-effort, model-configuration, and dependency-path overrides take precedence over their environment equivalents. Task-repository configuration remains independent from the ALA installation so a deployment can install only the task families it needs.

When hosted by Ploinky, the same operations may be exposed through its CLI, router, and WebChat. A Ploinky agent may also serve as an execution backend when its advertised capabilities match an A-Skill. Standalone operation must not depend on Ploinky.

Routing evaluation

Routing evaluation compares explicit task selection, default MainAgent-compatible detection, and symbolic routing before fallback. The shared corpus covers canonical instructions, paraphrases, multilingual requests, spelling errors, ambiguous and multi-step requests, missing parameters, and unsupported work.

Symbolic measurements include correct and incorrect direct decisions, abstention, fallback, and final correctness after fallback. A false confident decision receives a greater penalty than abstention because it bypasses the safe default route with the wrong method.

Distribution-owned contracts

The standalone distribution defines exit code 0 for success, 2 for usage or configuration errors, 3 for input and output errors, 4 for repository or A-Skill errors, 5 for execution errors, and 130 for interruption. Remote-agent protocols, task-workspace retention, retry limits, and symbolic-routing thresholds remain deployment contracts governed by the design specifications.
