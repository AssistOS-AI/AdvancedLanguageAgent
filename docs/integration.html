Documentation / Integration

Ploinky integration and routing evaluation

ALA operates as a standalone CLI and may also run as a Ploinky agent. Both forms preserve the same task-selection and result-separation contracts.

Deployment and configuration

User-level configuration comes from the current user's environment, with explicit manual overrides available for core runtime values. ALA reuses AchillesAgentLib model configuration and tags when present. Independently configured task repositories let a deployment install only the task families it needs.

When hosted by Ploinky, the same operations may be exposed through its CLI, router, and WebChat. A Ploinky agent may also serve as an execution backend when its advertised capabilities match an A-Skill. Standalone operation must not depend on Ploinky.

Routing evaluation

Routing evaluation compares explicit task selection, default MainAgent-compatible detection, and symbolic-first detection. The shared corpus covers canonical instructions, paraphrases, multilingual requests, spelling errors, ambiguous and multi-step requests, missing parameters, and unsupported work.

Symbolic measurements include correct and incorrect direct decisions, abstention, fallback, and final correctness after fallback. A false confident decision receives a greater penalty than abstention because it bypasses the safe default route with the wrong method.

Distribution-owned contracts

A concrete distribution defines the executable name, option syntax, package manifest, configuration files, environment-variable schema, exit codes, workspace retention, and numeric retry limits. The design specifications define the invariant behavior those choices must preserve.

Definitions

Ploinky
An agent-hosting environment that can expose registered agents through a CLI, router, and WebChat and advertise agents as execution backends.
WebChat
The Ploinky web conversation interface through which a hosted ALA agent may receive the same task requests as its CLI.
Routing evaluation
A comparison of selection paths using a shared corpus and metrics for direct decisions, abstention, fallback, and final correctness.
