# Advanced Language Agent Agent Guidance

## Scope

This repository defines [Advanced Language Agent](docs/index.html) (ALA), a CLI that exposes generic language-task execution infrastructure. [AchillesAgentLib](docs/wiki.html#definition-achilles-agent-lib) is authorized for `MainAgent`, `LLMAgent`, model selection, sessions, and ALA's internal `coding-agent` Code Skill. ALA mounts exactly the directories a caller supplies through `--cwd` and `--folder`; it does not discover, create, mount or overlay task skills.

## Runtime Skill Catalog

ALA distributes exactly one runtime skill: the generic `coding-agent` Code Skill that bridges `MainAgent` to Codex, OpenCode, Pi, or Claude Code. It is registered only when at least one backend is executable and is not a caller task skill. ALA implements no task catalog, repository manager, or symbolic router; callers own their own task methodology and directory layout.

## Repository Rules

- Write all documentation, specifications, and comments in English.
- Keep DS numbering gap-free. Reserve `DS003-main-behavior.md` for the single Main Behavior specification and regenerate `docs/specs/matrix.md` from DS metadata.
- Every ordinary DS file must use `Introduction`, `Core Content`, and `Conclusion` as its only standard top-level content sections.
- Every ordinary DS file must contain exactly the `title` and `summary` frontmatter fields, with `title` equal to its filename stem. Derive the DS identifier from the filename and do not add status or owner metadata.
- Put requirements, rationale, assumptions, limitations, alternatives, and contract boundaries in declarative prose under `Core Content`; do not create a separate decision log.
- Treat `DS001-coding-style.md` as the canonical source for coding style, runtime layout, file-size rules, and test organization.
- Follow the persistent-documentation rules in `DS001-coding-style.md` for every documentation change.
- Keep every prose block on one logical source line in Markdown and HTML; allow the browser to wrap text naturally at the full-width container boundary.
- Keep `docs/wiki.html` as the canonical page for specialized terminology and remove page-local definition sections. Link the first useful occurrence of a term to its wiki anchor, do not link a term to its own wiki entry from inside that entry, and do not repeat a link without additional navigational value. Keep the product introduction and definition on `docs/index.html`, omit an ALA entry from the wiki, and point explanatory links on “ALA” or “Advanced Language Agent” to `docs/index.html`.
- Make every top-level header control a submenu button and place every documentation destination inside exactly one subject-based submenu. Direct top-level header links are prohibited.
- Keep `docs/commands.html` synchronized with every CLI command, option, input rule, output rule, configuration precedence rule, and exit code exposed by the implementation.
- Mount semantics: `--cwd <path> [as <alias>]` is always writable, mounted at its canonical absolute path or at `/workspace/<alias>`; `--folder <path> [write] [as <alias> | at <absolute-path>] [expose]` is read-only unless marked `write`. Sources are canonicalized; reserved destinations and duplicate cwd targets are rejected. Ordinary overlapping folders are rejected; only an explicit read-only `expose` child may overlay a read-only folder ancestor. An export requires an explicit destination and may reveal only a strict subdirectory of an ignored source outside masked destinations, never the ignored root. Ordinary aliases remain masked. A read-only ancestor may contain the writable cwd, so ancestors must be mounted before descendants. When `--cwd` is omitted ALA creates a private temporary directory and retains it after the runtime closes. ALA must not interpret mounted contents.
- Distinguish execution lifetimes precisely: one-shot mode creates a new runtime and, when coding-agent execution is used, mounts the explicit caller-owned cwd or a retained temporary directory, then closes without implicit cross-process conversation continuation; explicit --session-id with --resume-session retains a pinned native conversation; interactive mode retains one runtime, the lazily created working directory, pinned coding backend, and native continuation until session exit.
- ALA owns and persists the conversation transcript of every explicit `--session-id` session as one append-only JSONL file at `$ALA_SESSIONS/sessions/<uuid>.jsonl`, defaulting to `<cwd>/.ala` when `ALA_SESSIONS` is unset; relative `ALA_SESSIONS` values resolve against `--cwd`. The file records `session`, `user`, `agent-message`, `tool`, `final`, `turn-end`, and `continuation` lines; lines are never rewritten, the last `continuation` record is the resumable native continuation, and readers ignore a trailing partial line. Embedding applications read transcripts only through the `advanced-language-agent/transcript` package export and never parse the files themselves. With `--control-stdin` and no task argument, `--task`, `--taskFile`, or payload, the first stdin record `{"type":"prompt","prompt","displayText"}` is the turn prompt: the coding agent starts only after it arrives, receives `prompt`, and the transcript `user` record holds `displayText` when present. There is no `--user-message-file` option. One-shot and interactive executions without `--session-id` persist nothing; their callers may opt into the structured standard-error event stream and own any history they keep.
- Native coding-agent permission policy is selected with `--permissions ask-for-approval|full-access`, defaulting to full-access inside Bubblewrap. Codex controlled execution uses app-server requests; OpenCode owns an authenticated native server per execution and must never rewrite project configuration. Claude Code runs with `--permission-mode bypassPermissions` for full-access and with `--permission-mode default --permission-prompt-tool stdio` for ask-for-approval, where each `can_use_tool` control request becomes an Allow once or Deny request. Hosts answer advertised opaque choices through control stdin, not conversation prompts or a host approval cache. Pi supports full-access only and requires the verified 0.85.1-or-compatible RPC lifecycle. Preserve explicit denial, cancellation, and unsupported-protocol errors.
- Node and prefix-installed dependencies remain usable through narrow read-only runtime mounts; never expose an entire caller home to find an interpreter.
- External integrations use generic read-only `--folder` mounts. The caller prepares dependencies and configuration and owns any socket protocol and cleanup. ALA must not parse Ploinky configuration or add Ploinky-specific mounts.
- Keep interactive slash commands synchronized with the CLI: `/help`, `/agent`, `/agent help`, `/agent list`, `/agent <codex|opencode|pi|claude> models`, `/agent <codex|opencode|pi|claude> model <model-name|default>`, `/agent use <codex|opencode|pi|claude>`, `/agent auto <prompt>`, `/agent <codex|opencode|pi|claude> <prompt>`, `/permissions [mode]`, `/quit`, and `/exit` are local commands and must never be routed to an LLM.
- When source changes behavior, interfaces, architecture, workflows, or constraints, update both the HTML documentation and affected specifications.
- Caller task methods and their specifications stay in the directory that owns them. A downstream consumer must not copy them into this project's `docs/` tree.

## Runtime Defaults

Interactive `/permissions [ask-for-approval|full-access]` is a local command. It reports or updates the next execution's native policy without resetting the runtime or persisting configuration. It does not create an approval-response channel, and Pi must continue to reject ask-for-approval.

The executable is `ala`. User configuration resolves from an explicit `--config <file>` first; otherwise ALA treats `ALA_CONFIG_PATH` as a root directory, falls back to `$HOME`, and uses `<root>/.ala/config.json`. The file accepts only the optional fields `codingAgent` (`codex`, `opencode`, `pi`, or `claude`), `models` (one native model per backend), and `efforts` (one native effort per backend that has a configured model). Any other field, including the former `version` and `codingAgents` layout, must fail with "ALA configuration supports only codingAgent, models and efforts"; ALA keeps no migration or legacy reader. A missing file is `{ models: {}, efforts: {} }`. Explicit session mode stores the session transcript, including the pinned backend and native continuation, under `ALA_SESSIONS` or `<cwd>/.ala`; `<home>/.ala/sessions` is not used, and `--home` and `--cwd` remain required with `--session-id`; `--ca` is optional there and defaults to `auto`. While an interactive terminal waits for MainAgent or coding-agent execution, ALA must animate `Thinking.`, `Thinking..`, and `Thinking...` on the diagnostic stream, then clear the indicator before results or errors; non-terminal and single-shot output must remain unchanged.

The default route uses AchillesAgentLib `MainAgent` for general execution. Explicit `--ca`/`--agent` selection, `--session-id`, or any active `--folder`, routes execution to the coding agent. ALA resolves the library from `--achilles-path` or `ACHILLES_AGENT_LIB_PATH`, then a sibling checkout, then the installed `ploinky-agent-lib` package.

At process startup, ALA detects Codex, OpenCode, Pi, and Claude Code through their binary override variables (`CODEX_BIN`, `OPENCODE_BIN`, `PI_BIN`, `CLAUDE_BIN`), standard installation locations, and `PATH`. When at least one is available, ALA registers its generic `coding-agent` Code Skill with MainAgent. `--agent` forces this execution path and `ala agent list` reports available backends in the fixed order Codex, OpenCode, Pi, Claude Code. `auto` resumes a session's saved backend; otherwise it uses the configured `codingAgent` when installed, then the first available backend in that fixed order. The order is not configurable and `ALA_CODING_AGENT_PRIORITY` no longer exists. Interactive `/agent use <name>` must persist `codingAgent`. Interactive model-list commands must query the selected agent's native catalog adapter, and model-set commands must persist a backend-specific value under `models` and clear that backend's entry in `efforts`. A configured value must be passed on every invocation of that backend; when no value is configured, ALA must omit the model option so the CLI uses its own default. With coding-agent execution, `--model` replaces the selected backend's configured model for one invocation and drops its configured effort when the model differs; `--tag`, `--reasoning-effort`, and `--model-config` must not be reinterpreted as coding-agent settings. Web search is always enabled: Codex runs with `--search` (app-server `web_search="live"`), OpenCode receives `OPENCODE_ENABLE_EXA=1` with `websearch` and `webfetch` allowed, Claude Code keeps its built-in `WebSearch` and `WebFetch` tools, which are on by default, and Pi has no web search. There is no `--websearch` option or `/websearch` command. Every coding-agent execution and native model-list process must run inside a fail-closed Linux Bubblewrap namespace. ALA must use the already installed backend through a read-only runtime bind and must never reinstall it. The launcher must clear inherited environment variables, reconstruct a backend-specific allowlist, and remount the sandbox root read-only. The caller's cwd and folders appear at their canonical paths, or under `/workspace/<alias>`, and unrelated host paths must remain absent; only controlled backend authentication/state paths may be mounted read-write. Explicit session mode persists backend and native continuation as `continuation` records in the session transcript; `--resume-session` must fail when the transcript or its native continuation cannot be recovered, and a session that already has a native continuation must be resumed rather than restarted. Pi native session files remain in `<workspace>/.ala-pi-sessions`. Claude Code keeps all its state, including the login and `.claude.json`, under `CLAUDE_CONFIG_DIR=/home/ala/.claude`, which is `<home>/.claude` with `--home` or the host's `CLAUDE_CONFIG_DIR` or `~/.claude` without it. Its sandbox also sets `IS_SANDBOX=1`, because the sandbox may run as uid 0 and Claude Code refuses `bypassPermissions` as root otherwise, and `DISABLE_AUTOUPDATER=1`. The Claude adapter relies on the `initialize`, `can_use_tool`, and `interrupt` control requests that the Claude Agent SDK exchanges with the same CLI. An interactive process must retain native continuation and the same working directory until session shutdown, and replace the `Thinking` indicator with supported live backend output when the first event arrives.

All direct model interactions owned by ALA must use AchillesAgentLib's `LLMAgent` configured through runtime configuration and environment values. Coding-agent interactions must use the internal Code Skill and the selected agent's native CLI. Manual configuration overrides must remain available.
